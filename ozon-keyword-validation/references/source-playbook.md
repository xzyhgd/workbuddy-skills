# 数据源、读数与证据手册

## 允许来源与优先级

1. 本店 Ozon Seller API 的两条白名单只读端点返回的 SKU 标识和标题。
2. Ozon Seller 页面中的搜索查询报表或用户从该页面导出的原始数据。
3. Ozon 前台 PDP，用于核验标题、属性词和 SKU 关联。
4. Wordstat 频次页面与 Dynamics 页面的可见原始数据。
5. 用户提供的原始截图、导出表与商品参数。

第三方文章、搜索摘要、社媒或模型记忆只能帮助提出候选词或解释假设，不能填充任何最终数据单元格。

## Ozon Seller API 只读规则

- 仅由用户授权的受信任宿主使用其安全存储中的凭据。
- 只允许：
  - `POST https://api-seller.ozon.ru/v3/product/list`
  - `POST https://api-seller.ozon.ru/v3/product/info/list`
- 仅读取本店 `offer_id`、俄语标题和作为属性词依据的参数。
- 不保存请求头，不截图网络面板中的鉴权内容，不把响应原样复制到包含隐私/鉴权字段的日志。
- 出现 401、403、429、5xx、字段变化或网络失败时，记录脱敏错误类型；不改用其他 API 路径，不循环重试，不要求用户交出凭据。

## Ozon 搜索查询页

- 固定只读入口：`https://seller.ozonru.cn/app/analytics/what-to-sell/all-queries`（国际站 `https://seller.ozon.ru/app/analytics/what-to-sell/all-queries`）。`/app/analytics/search-queries` 不是本报表，主区域空白时停止并改用正确入口，不得在错误页面继续抄数。
1. 记录页面实际报表名称、查询词、筛选、地区/仓或可见维度、窗口标签与抓取时间；绝对起止日期不可见时按“窗口口径”停下请用户拍板。
2. 逐列保存原始列名、列位置及原始值。不要预设页面一定有八列；若已确认有“搜索查询”加七项数值，也仍必须记录页面真实表头。
3. 只有与查询词精确相同的行可抄录；返回相似长尾词或空结果时写 `no_exact_match`，不挪用其他行数值。
4. 截图必须能定位关键词、数值、筛选和窗口。无法单图覆盖时分片截图，并在 CSV 以分号列出全部证据文件。
5. 页面排序、分页、Top N 截断或筛选不可用时，记录覆盖状态。局部结果不代表真实零值。
6. 只读浏览与导出允许；禁止点击启动推广、编辑商品、改价、库存、上下架、保存设置或任何提交按钮。

## Wordstat 网页

- 频次只取 Phrasing/Top queries 表格首行 `Number of queries`；标题里的 `along with ... : N` 是同时搜索的其他词数量，不是频次。`No impression data` 或空结果写 `UNVERIFIED` 并截图，不写 0。
1. 频次与趋势分别记录实际输入表达式、地区、设备、窗口起止日期、抓取时间和截图。
2. 双引号只限制词数；词序需用 `[]`，词形需用 `!`。不根据记忆假定页面支持某种组合运算符；以页面实际接受的表达式为准。
3. Dynamics 页面可能不支持频次页全部运算符。记录实际可执行的趋势查询式，并写明与频次查询是否完全一致。
4. 出现“may be unstable”、空结果或瞬时错误时，单词单来源最多尝试三次；记录每次时间与结果。第三次仍失败，停止该词该源并写入 `BLOCKED.md`。
5. 批量提交后强制切回频次视图再解析；解析结果与截图冲突时以截图为准，不保留脚本残留值。
6. 不把 Wordstat 搜索展示次数解释为订单、买家数或 Ozon 站内搜索量。

## 窗口口径

- Ozon 非 Premium 账号可能只显示 `时期: 7 天`，点击控件弹出订阅广告。不得把相对窗口伪装成绝对起止日期。
- 停下列出三个选项请用户拍板：严格判 `UNVERIFIED` / 接受相对窗口加抓取日 / 由用户提供绝对日期。决定写入 `run_manifest.json` 的 `ozon_window_decision`；未获决定不进入判定。

## 人机验证与受限访问

出现 Qrator、Captcha、滑块、307 连续跳转后 403、异常验证页或要求更换网络时：

- 立即停止自动化读取；
- 不换代理、不解题、不注入 Cookie、不关闭 TLS 校验、不改浏览器扩展或自动化设置；
- 由用户在自己的浏览器完成人工操作；
- 无法恢复时仅分析用户提供的截图或导出，并标为“部分验证”或 `UNVERIFIED`。

## 截图质量与命名

- 每个关键词每个来源至少一份证据；频次和趋势若不能同图定位，分别保存。
- 图片大于 20KB 是最低文件健康条件，不等于证据充分。
- 推荐命名：`ozon-K01-a.png`、`yandex-K01-frequency.png`、`yandex-K01-dynamics.png`、`reverse-check-ozon-K01.png`。
- 截图中不得包含 API Key、Cookie、密码、Token、完整个人联系方式或与本任务无关的敏感信息；发现时先遮蔽或重新截取，再进入证据目录。
- 交付前核对 `PROGRESS.md`、`run_manifest.json` 与实际证据文件数量一致；清理 `_page.html` 与 `_` 开头临时文件，避免任务残留进入交付包。
