# Ozon × Wordstat 关键词交叉验证

## 适用范围

用于把本店 Ozon 商品的俄语标题与真实参数转成可复跑的种子词、站内搜索查询指标与 Yandex Wordstat 证据，并给出绿、黄、红的交叉判断。适用于“把我店里 SKU 的词跑一遍”“这个 Ozon 词是真需求还是假象”“帮我用站内和 Wordstat 验证俄语关键词”“换一批词按上次规则重跑”等请求。

不用于改商品标题、价格、库存、广告、类目、上下架或保存后台设置；不用于绕过 Qrator、Captcha、403、滑块或其他访问控制；不在 Skill 文件、脚本、截图、日志或输出中保存 API Key、Cookie、密码或 Token。

## 开始前：环境与安全路由

1. 识别本次所需能力：本店 SKU 标题读取、Ozon 站内查询、Wordstat 频次、Wordstat 趋势、截图存证、数据汇总或仅离线分析。
2. 先运行 `scripts/check_environment.py`，按结果路由：
   - `ready`：直接进入对应步骤；
   - `partial`：继续已就绪的功能，输出中标注降级范围；
   - `needs_setup`：只展示本次缺失的必需条件，等待用户配置后重检；
   - `unavailable`：按 `@references/setup-guide.md` 的恢复和降级规则处理。
3. 严格使用只读路径和操作。Ozon API 仅允许由受信任宿主向 `https://api-seller.ozon.ru/v3/product/list` 和 `https://api-seller.ozon.ru/v3/product/info/list` 发起最小只读请求；绝不要求用户粘贴凭据，也不在输出中回显凭据。
4. 使用人工浏览器读取 Ozon 或 Wordstat 时，先观察页面。遇到登录失效、人机验证、307 后转 403、Qrator、Captcha、滑块或页面限制公告时，停止自动化读取；不换代理、不解挑战、不改浏览器/扩展设置、不关闭 TLS 校验。等待用户在自己的浏览器中处理，或转为用户提供的截图与导出材料。
5. 在用户确认的项目目录内建立一次运行目录。默认目录名为 `ozon-keyword-pipeline/`；只能在该目录中写入数据、证据、进度与阻断记录。未获确认不得写入任何个人目录或系统目录。
6. 加载与当前步骤对应的材料：
   - 数据列与证据关联：`@references/data-schema.md`
   - 冻结判定规则：`@references/decision-rules.md`
   - 数据源、截图与失败处理：`@references/source-playbook.md`
   - 换词复跑 SOP：`@references/rerun-sop.md`
7. 遇到口径不明、窗口不可核验、页面路径不确定或需要用户在自己的浏览器确认时，立即停下，把已取得的证据与可选项列给用户检查；没有得到明确决定前，不进入判定、不猜数值、不替用户选路径。

## 全局证据规则

1. 每个数字必须关联截图或原始导出，并记录来源、关键词、可见时间窗起止日期、抓取时间、筛选条件与证据文件名；没有证据的单元格写 `UNVERIFIED`，不得补造。
2. Ozon 搜索查询热门度是相对指数；不得与 Wordstat 的绝对频次直接比较大小。两源只分别参与本批次的排序和中位数判断。
3. 原始 Ozon 页面列名、数值与顺序原样保存。页面列发生变化时记录 `schema_changed`，先更新字段映射，再停止与旧批次直接比较。
4. Wordstat 频次查询与趋势查询分别记录实际表达式、窗口、地区、设备与可比性说明。双引号限制词数，不固定词序或词形；方括号固定词序；感叹号固定词形。Dynamics 页面只使用页面实际接受的查询表达式，不把不同口径的趋势伪称为精确短语趋势。
5. 默认显示的“最近 7 天”或“最近 30 天”不是窗口证据。必须读取页面可见日期范围或导出元数据；看不到起止日期时标 `window_dates_unverified`，该行不得进入最终判定。
6. 同一关键词同一来源连续失败 3 次，停止该来源的该词处理，写入 `BLOCKED.md` 并继续其他词。不得无限重试。
7. Ozon 站内只读入口固定为 `https://seller.ozonru.cn/app/analytics/what-to-sell/all-queries`（国际站 `https://seller.ozon.ru/app/analytics/what-to-sell/all-queries`）。`/app/analytics/search-queries` 不是本报表入口，主区域空白时应停止并改用正确入口，不得在错误页面继续抄数。
8. Ozon 站内仅精确命中查询词的那一行可抄录；返回相似长尾词或空结果时写 `no_exact_match`，不得挪用邻近行数值。
9. Wordstat 频次只取 Phrasing/Top queries 表格首行 `Number of queries`；标题中的 `along with ... : N` 是共同搜索词数量，不是频次。`No impression data` 或空结果写 `UNVERIFIED` 并截图，禁止写 0。
10. 页面批量解析或视图切换结果不稳定时，以可见截图为唯一真相源；不得用残留 DOM 值或未确认解析结果填表。
11. 绝对起止日期不可见时，先把三个选项交给用户拍板：严格判 `UNVERIFIED` / 接受相对窗口加抓取日 / 由用户提供绝对日期。未获决定前停在 `BLOCKED.md`，不自行采用相对窗口，不编造日期。
12. CSV 用标准库 `csv` 写入并正确转义俄语、百分号与逗号；交付前核对 `PROGRESS.md`、`run_manifest.json` 与实际证据文件数量一致，并清理 `_page.html`、`_` 开头等临时文件。

## 执行流程

### 1. 建立进度与阻断记录

1. 在运行目录创建 `PROGRESS.md`，开头不超过 10 行写明：目标、固定顺序、最大风险、运行日期、当前阶段与停止时间。
2. 创建 `BLOCKED.md`。没有阻断时写“无”；有阻断时先写发生时间、任务、证据、已尝试次数、影响、可恢复条件和是否继续其他项。
3. 创建 `data/run_manifest.json`，记录本次词批、地区、设备、各来源窗口、字段映射版本、冻结规则哈希、操作人和运行起止时间。不得记录任何凭据。

### 2. 提炼 SKU 种子词

1. 从只读 Ozon Seller API 返回或用户提供的导出中读取本店 SKU 的 `offer_id`、俄语标题与可复核参数。API 返回只作为原始输入保存，不在结果中展示请求头。
2. 每个 SKU 提炼一个俄语核心品类词，使用名词词典形；将中文释义和提炼依据写入 `data/seeds.csv`。
3. 若多个 SKU 是同一生态位、标题无法支持独立品类词或标题/参数缺失，不强凑不同词；保留该 SKU、标记 `seed_pending` 并写入 `BLOCKED.md`。
4. 当前批次优先处理 5 个可核验 SKU；数量不同则如实记录实际 SKU 数，不伪造“五行”验收。

### 3. 生成并冻结关键词批次

1. 为每个有效核心词生成 1–2 个长尾词，总目标为 10–12 个；属性词只能来自该 SKU 的标题、参数、PDP 或 Ozon 站内返回的高频变体。
2. 在 `data/keywords.csv` 记录核心词、关键词、构造方式、属性来源、来源 SKU 与 `candidate` 状态。
3. 先用核心词在 Ozon 站内搜索查询页确认高频长尾候选，再更新关键词表；平台返回的高频长尾优先于自编组合。
4. 关键词批次进入数据读取前冻结；后续发现更好的词只能写入下一批，不能替换本批已判定的词。

### 4. Ozon 站内验证

1. 在只读的 Ozon 搜索查询报表（见全局规则 7）逐词查询，逐列抄录页面实际列名、数值与顺序；不按记忆补列。只有精确命中查询词的行可抄录，相似长尾词按 `no_exact_match` 处理。
2. 对每词保存至少一份能定位关键词、页面数据、筛选条件和日期范围的截图；一张图放不下时增加截图。文件名采用 `evidence/ozon-<序号><分片>.png`。
3. 原始页面读数写入 `data/ozon_raw.csv`；页面原始列名与标准字段的对应关系写入 `data/ozon_column_mapping.csv`。只有确认“关键词字段 + 7 个数值指标”时，才将 7 项进入结果表。
4. 每行保存 Ozon 证据编号、页面显示的窗口标签（如 `7d_relative`）、抓取时间和覆盖状态；只有用户拍板接受相对窗口后，才把抓取日写入窗口字段。截图过小、日期不可见、字段不全或页面报错时写 `UNVERIFIED` 或相应状态，不填猜测数字。

### 5. Wordstat 全网验证

1. 逐词进入 Wordstat 网页，明确记录地区、设备与页面可见窗口。频次查询使用记录在 `wordstat_frequency_query` 的表达式；趋势查询使用记录在 `wordstat_dynamics_query` 的页面实际表达式。
2. 频次取 Phrasing/Top queries 表格首行 `Number of queries`，不得取标题中的 `along with ... : N`；记录近 30 天展示值和实际窗口起止日期。趋势记录近 12 个月的升、平或降，并保存判定依据。出现“may be unstable”或空结果时，最多重试 3 次；`No impression data` 写 `UNVERIFIED` 并截图，不写 0。
3. 每词保存至少一份频次证据和一份趋势证据；可合并在同一截图时允许共用文件名，但必须能定位两个读数。文件名采用 `evidence/yandex-<序号><分片>.png`。
4. 原始读数写入 `data/yandex_raw.csv`，包括两个查询式、可比性说明、频次、趋势、窗口、地区、设备、时间戳与全部证据编号。
5. 批量提交后强制切回频次视图再解析；解析结果与截图冲突时以截图为准，不保留脚本残留值。

### 6. 冻结阈值、交叉判定与反向验证

1. 趋势方向算法在读取前冻结：默认取 Dynamics 最近 12 个月，前 6 个月均值与后 6 个月均值比较，≥+10% 为 `up`、≤−10% 为 `down`、其余 `flat`；改用其他算法必须先写入 `data/run_manifest.json` 并取得用户确认，判定期间不得更换。在写入任何绿黄红结论前，按照 `@references/decision-rules.md` 从本批完整且可核验数据计算中位数，并将冻结规则原文、输入行 ID 与结果写入 `data/run_manifest.json`。
2. 绿：站内热门度与加购转化率均不低于对应有效样本中位数，且 Wordstat 频次不低于有效样本中位数、趋势不是降。
3. 黄：仅一侧强，或数据存在允许的可解释不一致；必须填写固定 `yellow_reason_code` 与文字说明。
4. 红：站内侧与 Wordstat 侧均弱，且两侧证据完整、窗口可核验。
5. 任何关键数据缺失、窗口未核验、字段映射未确认、查询口径不可解释或截图不能定位时，判定为 `UNVERIFIED`，不纳入绿黄红数量。
6. 抽 1 个已完成关键词，在相同地区、设备、筛选和窗口设置下重新打开 Ozon 与 Wordstat 页面；保存两源复现证据。数值不一致时先比对窗口、地区、设备、缓存、更新时点和页面排序；无法解释则将该词标为 `UNVERIFIED`，保留两次证据，不挑选更好看的数字。
7. 机械规则产生反直觉结果时（例如加购转化率高于中位仍判红），在 `sop.md` 写明 `rule_limitation_note` 供人工判断；不得因此改阈值或分类。

## 交付与自查

1. 最终生成 `data/keywords_result.csv`，包含关键词、已映射的 7 项 Ozon 数值、Wordstat 频次/趋势、两个查询式、窗口、地区、设备、绿黄红或 `UNVERIFIED`、原因码、全部证据编号和时间戳。
2. 生成 `sop.md`，必须包含五步流程、冻结规则、本批一行真实示例、失败模式与对策、Wordstat API 升级路径、换词复跑说明和未覆盖范围。
3. 交付前逐项检查：
   - 每个非 `UNVERIFIED` 数值都能追溯至截图或原始导出；
   - Ozon 指数和 Wordstat 频次没有被跨源直接比较；
   - 所有阈值在判定前冻结，缺失值没有进入中位数；
   - 每个黄灯都有原因码；
   - `BLOCKED.md` 存在且写有“无”或具体阻断；
   - 反向验证有两源证据与比对结果；
   - 没有凭据、Cookie、Token、密码或后台写入操作痕迹；
   - `PROGRESS.md`、`run_manifest.json` 与实际证据文件数量一致，且无 `_page.html`、`_` 开头临时文件；
   - 若出现机械规则局限，已写 `rule_limitation_note`。
4. 运行达到 3 小时或完成 12 个词的完整轮次时停止，保存当前完整证据与缺口，如实报告完成数、`UNVERIFIED` 数、阻断原因和下一步。
