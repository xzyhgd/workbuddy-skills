# Ozon 社媒—供给缺口反向选品

## 目标与触发

用于把“某品牌 / 某机型 / 某类配件好不好卖”转化为可执行的 Ozon 选品结论。适用于：

- 挖掘 Ozon 俄罗斯站的供给缺口、用户痛点、价格带和首测 SKU；
- 判断某机型生态（例如 Creality、Bambu Lab、Flying Bear、PICASO、商用车柴暖、专业设备等）是否值得备货；
- 对“搜索结果少”“评论少”“竞品少”的蓝海判断进行反证；
- 突破“国内搜不到俄系副厂/平替件”的跨国供应链命名与行业标准信息差；
- 更新俄罗斯品类研究报告或生成新品决策简报。

将最终目标限定为：识别“真实需求存在、供给尚薄、兼容性可控、能用小批量验证”的 SKU，不把低评论数本身当作需求证据。

## 核心原则

1. **至少双轴验证。** 同时验证需求侧与供给侧；优先增加第三轴“买家评价 / 售后痛点”。
2. **评论不是销量。** Ozon 评论是累计链接沉淀的代理指标，偏向老链接，不等同于月销、真实市场规模或新品需求。
3. **保有量不是全市场。** 社区认领量仅代表样本内装机基础；只能用于机型之间的相对比较，并明确来源、抓取日期和样本边界。
4. **卖家数比零评论更能识别红海。** 采用下列排除规则：
   - `零评论 + 多卖家`：通常是刚铺货或同质化价格战，不视为蓝海；
   - `零评论 + 单卖家 + 高保有量 / 高讨论`：优先作为真实缺口候选；
   - `高评论 + 无保有量 / 无社媒支撑`：标记为假信号，检查关键词堆叠、跨型号混卖、卖家运营或数据归类错误。
5. **无供给必须复核。** 对任何“无货 / 缺货 / 没有竞争”的判断，至少用一次精确型号、零件号或兼容性关键词复查，防止 Ozon 类目预测或语义改写造成误判。
6. **跨语言/跨行业标准映射（破解国内供应链命名差）。** 俄罗斯终端叫法、欧美原版技术源头与中国工厂出厂名称往往完全脱节。在判定国内“无货”之前，必须沿“俄方本土件号/俗称 → 欧美逆向技术源头/标准件 → 国内产业带习惯命名”进行三次映射，不得仅用俄语字面翻译在 1688/工厂端检索。
7. **推断与事实分开写。** 数据、观察、推断、行动建议必须分栏；不得把行业经验、标题样本或代理指标写成平台规则或统计结论。
8. **无法验证时如实降级。** 记录失败来源、受限原因及其影响，降低置信度；不得编造评论、文章样本、销量或比例。

## 执行流程

按顺序执行；如数据源不可用，保留已完成证据，进入“诚实降级”而不是跳过关键验证。

### 1. 确定决策问题与边界

明确以下字段：

- 目标市场：Ozon Russia；币种、履约模式和首测预算；
- 产品范围：品牌、机型、耗材、易损件、升级件或维护包；
- 兼容边界：具体型号、代际、尺寸、电压、接口、左右版本、固件 / RFID 限制；
- 目标用户：新手、存量维修用户、改装用户、小型工作室或教育机构；
- 决策形式：研究结论、候选池、首测 SKU、补货建议或停止项。

先拆解“泛品类”到可采购的 SKU 族。避免直接得出“Ender 3 配件值得做”这类不能执行的结论。

### 2. 建立需求侧证据

优先顺序：机型 / 品牌社区数据库 → 本土社媒与论坛 → 视频 / 搜索趋势 → 用户问答与评论。

对每个机型或 SKU 族记录：

| 字段 | 说明 |
|---|---|
| 来源与抓取日期 | URL、页面标题、日期、登录 / 网络限制 |
| 装机代理 | 社区认领保有量、机型条目、订阅 / 讨论群规模等 |
| 内容强度 | 文章数、帖子数、讨论频率；可计算“内容数 / 保有量” |
| 主题线索 | 维修、调平、堵头、漏料、改装、稳定性、耗材兼容等 |
| 证据等级 | 原始页面、搜索摘要、二手转述、无法复现 |

对 3DToday 等机型库，可用“文章数 / 认领保有量”比较同品牌机型的存量维护 / 改装讨论强度；不得将其解释为真实故障率或全俄销量。

### 3. 建立 Ozon 供给侧快照

对每个候选 SKU 族，使用泛词和精确词分别搜索，记录：

| 字段 | 最低要求 |
|---|---|
| 检索词 | 泛关键词 + 精确型号 / 零件号 / 兼容性词 |
| 链接数 | 搜索结果中可辨认的真实商品链接数 |
| 卖家数 | 独立卖家数量或同款卖家密度 |
| 累计评论 | 每条链接及总量，注明抓取日期 |
| 价格带 | 最低 / 主流 / 高客单价格，币种为 ₽ |
| 可售状态 | 在售、缺货、预售、跨境长时效等 |
| 商品边界 | 是否混入不相干类目、兼容机型是否一致 |

执行复核：

1. 先搜泛词，识别平台联想、类目重定向和关键词污染；
2. 再搜准确型号、零件号、俄语部件名和主要同义词；
3. 对“没有供给”的方向至少截图 / 记录一次精确词结果；
4. 对高评论链接打开商品页，确认评论对应的具体版本，避免把跨型号链接误计入。

### 4. 抓取买家痛点而非只统计评论

优先查看 1–3 星评价、带图评价、问答、售后相关表述。将原文、翻译、链接、星级、日期与对应 SKU 绑定，归入：

- 尺寸、孔距、线序、电压、接口不兼容；
- 热端、喷嘴、挤出、堵塞、漏料、温控与耗材适配；
- 包装、运输、缺件、安装说明、质控；
- 耐久性、磨损、异响、轴承 / 皮带 / 丝杆问题；
- 价格、到货、售后、替换周期。

不要用一条评价代表全类目。将评论原话作为问题存在的证据，将频率判断写为“样本观察”，并标注样本量。

### 5. 计算错配并剔除假空白

使用如下决策框架，不要求伪精确总分：

| 维度 | 高分信号 | 低分 / 排除信号 |
|---|---|---|
| 装机基础 | 高保有量、稳定存量机型 | 无条目或无证据支撑 |
| 社媒强度 | 高内容数 / 高篇台、明确痛点 | 只有营销内容或无法复现 |
| 供给薄度 | 少链接、少卖家、关键价格带空缺 | 多卖家同质化、低价竞争 |
| 需求沉淀 | 同类可见真实成交 / 评价 | 全部 0 评且无外部支撑 |
| 痛点可解决性 | 规格明确、可标准化验证 | 需要复杂售后或兼容性不透明 |
| 经济性 | 能覆盖 FBS、运费、退货、合规与质控 | 低客单、易碎、退货成本高 |

重点识别“价格带错配”：低价维修小件已有评价，而高客单升级套件缺少真实成交时，不能直接把高价段定义为 P0；先用相近产品的成交迹象、社媒升级讨论和小批量测试确认。

### 6. 输出 P0 / P1 / P2 决策

- **P0：优先首测。** 有装机与社媒支撑；Ozon 供给薄或关键价格带存在空档；规格可控；存在清晰采购和验证路径。
- **P1：观察 / 补证。** 存在部分信号，但卖家数、需求强度、兼容性或经济性仍需验证。
- **P2：暂不进入。** 需求弱、假空白、价格战、型号衰退、强绑定原厂、售后风险不可控或数据无法支撑。

每个 P0 必须给出：具体 SKU 定义、兼容型号、目标价格带、首批数量假设、验货项、主图 / 标题关键词、退出条件与下一步验证动作。

## 最低交付格式

交付研究结论时，按以下结构输出：

1. **结论摘要：** 最多 3 个 P0 / P1 / P2 决策与置信度；
2. **证据表：** 社媒 / 保有量、Ozon 链接 / 卖家 / 评论 / 价格、买家原话；
3. **错配解释：** 为什么是“真缺口”或“假空白”；
4. **SKU 行动卡：** 规格、兼容性、目标价、首测、验货与退出规则；
5. **边界与未完成项：** 不可访问数据、样本限制、待验证假设；
6. **来源清单：** URL、抓取日期、访问限制和复现前提。

详细字段定义与评分口径见：

- `references/evidence-schema.md`
- `references/scoring-rubric.md`
- `references/source-playbook.md`

## 数据受限与诚实降级

出现登录墙、反自动化挑战、动态加载失败、搜索结果无法稳定分页或评论不可访问时：

1. 停止绕过访问控制，不求解挑战、不使用未授权代理、不关闭安全校验；
2. 记录来源、访问时间、限制现象及其对结论的影响；
3. 使用可访问的独立来源做交叉验证，但不得冒充为官方原文；
4. 将结论从“已证实”调整为“候选 / 待验证”，降低优先级；
5. 不把“无法抓到数据”写成“没有需求 / 没有供给”。

## 云端报告更新与质量检查

当用户指定 WorkBuddy 资料库云端报告为唯一更新源时，直接更新云端页面，不用本地无锚点副本覆盖。对于页面型报告：

1. 创建页面事务并下载当前云端版本；
2. 将下载内容保留为 baseline；
3. 在工作副本中插入内容，保持已有 `data-page-node-id` 锚点；
4. 修改前做幂等检查，防止同一节重复插入；
5. 用双向 diff、章节唯一性、HTML 开闭标签平衡和 LF 换行检查验证；
6. 上传并提交事务；
7. 回读云端版本，核对章节、字节数、结构和平衡；
8. 仅在核验通过后宣称发布完成。

禁止将临时目录或工作目录作为事务清理目录。若使用 Python 改写 HTML，使用 `newline=''` 保持原有 LF，避免整页无意义替换。

## 禁止事项

- 不得只凭 Ozon 评论数、搜索结果数或单个爆款链接下结论；
- 不得把社媒认领量、内容数或评论数写成真实销量；
- 不得把标题级观察伪装成全量文章主题分类；
- 不得忽略卖家数、同质化和兼容性，只因“零评论”就称蓝海；
- 不得把关键词污染、平台类目预测结果当作产品供给事实；
- 不得在证据不足时承诺销量、利润或绝对成功率；
- 不得绕过站点反自动化控制获取数据。

## 已验证的校准案例

- **Ender 3 家族：** 高社区保有量与高讨论沉淀、相对低的配件供给沉淀，构成值得进一步拆 SKU 测试的真实错配。优先从双 Z 轴套件、直驱挤出机升级套件等具体方向验证，而不是泛做“Ender 3 配件”。
- **SPARKX i7：** Ozon 部分链接有评价，但社区机型库缺乏装机和内容支撑，不能仅凭评论将其定为 P0。属于“供给侧信号无法被需求侧支撑”的反例。
- **Creality Hyper PETG：** 泛词检索可能被 Ozon 类目预测污染；经精确型号词复核后可发现真实供给。因此“无供给”必须经过精确词复核。
- **Planar 44D 柴暖鼓风机 (сб.1881-01)：** 俄罗斯官方 Advers 溢价极高（9,600–14,000 ₽），副厂 2.8 分低评集中于“装上即啸叫哨音”。国内若直接搜“Planar 44D”结果几乎为 0，因为其技术源自德国 Eberspächer（埃贝赫 D4/D2），国内产业带一律命名为“埃贝赫 D4 鼓风机总成”且成本仅数十至百余元。通过“俄方型号 → 德系源头 → 国内通用名”的跨国映射，成功锁定高客单 P0 首测与 100% 动平衡防啸叫验货方案。
